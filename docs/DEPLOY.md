# Публикация «MVST FUR PRODUCTION» на сервере (чтобы работало без ноутбука)

Цель: сайт работает круглосуточно по адресу `https://…`, заказчик заходит по логину и паролю и тестирует на реальных данных.
Выбранный путь: **облачный сервер (VPS) на Timeweb Cloud + Docker**. Всё нужное уже есть в репозитории:
`Dockerfile`, `docker-compose.prod.yml` (база + приложение + HTTPS), `deploy/Caddyfile`, `deploy/.env.prod.example`, `deploy/backup.sh`.
Ориентир по времени: 1,5–3 часа в первый раз. Стоимость: небольшая месячная плата за сервер (тарифы смотрите на timeweb.cloud — цены я не проверял; для теста хватает 2 ядра, 4 ГБ памяти, 40–60 ГБ диска).

## Почему VPS, а не «Приложения» Timeweb и не управляемая база
- Приложение хранит загруженные документы (PDF, Excel, фото) **на диске сервера**. На сервере с Docker и постоянным диском это работает сразу. В платформенных «Приложениях» диск обычно временный — файлы пропадали бы при каждом обновлении (проверьте в документации Timeweb, если решите идти этим путём).
- База PostgreSQL в том же Docker — проще и дешевле. Если позже понадобится управляемая база Timeweb, меняется одна строка `DATABASE_URL`.

## Что понадобится заранее
1. Аккаунт на https://timeweb.cloud (регистрация по почте/телефону, пополнить баланс).
2. Компьютер с терминалом (macOS: приложение «Терминал»).
3. Доступ к репозиторию на GitHub `PetrFedin/fur-erp` (репозиторий приватный — сервер будет читать его по ключу, шаг 6).
4. (Необязательно) своё доменное имя. Без домена — используем адрес вида `185-12-34-56.sslip.io` (бесплатно, HTTPS работает).

## Шаг 1. Заказать сервер
1. Зайдите в панель Timeweb Cloud → «Облачные серверы» → «Создать сервер».
2. Образ: **Ubuntu 24.04** (если в списке есть «Docker» в маркетплейсе — можно взять его, тогда шаг 4 пропускается).
3. Конфигурация: 2 vCPU, 4 ГБ RAM, диск 50 ГБ NVMe. Регион: Москва или Санкт-Петербург.
4. Доступ: выберите **SSH-ключ**. Если ключа нет — на своём компьютере выполните в Терминале:
   ```bash
   ssh-keygen -t ed25519 -C "fur-erp-server"
   cat ~/.ssh/id_ed25519.pub
   ```
   Скопируйте напечатанную строку и вставьте в Timeweb как новый SSH-ключ.
5. Нажмите «Создать». Через 1–3 минуты у сервера появится **IP-адрес** (например `185.12.34.56`) — запишите.

## Шаг 2. Подключиться к серверу
```bash
ssh root@185.12.34.56
```
(вместо IP — ваш). На вопрос «Are you sure…» ответьте `yes`.

## Шаг 3. Базовая защита
```bash
apt update && apt upgrade -y
apt install -y ufw
ufw allow 22/tcp
ufw allow 80/tcp
ufw allow 443/tcp
ufw --force enable
```
Порт базы данных наружу не открывается (в `docker-compose.prod.yml` его нет) — это сделано намеренно.

## Шаг 4. Установить Docker
```bash
curl -fsSL https://get.docker.com | sh
docker --version
docker compose version
```
Должны напечататься версии обеих команд.

## Шаг 5. Выбрать адрес сайта (DOMAIN)
- **Вариант А — быстрый, без домена.** IP `185.12.34.56` → адрес `185-12-34-56.sslip.io` (точки заменить дефисами). Ничего покупать и настраивать не нужно.
- **Вариант Б — свой домен.** Купите домен (например на Timeweb), в DNS добавьте запись типа **A**: имя `erp` (получится `erp.вашдомен.ru`) → значение `185.12.34.56`. Подождите 5–30 минут и проверьте командой `ping erp.вашдомен.ru` — должен отвечать ваш IP.

## Шаг 6. Скачать проект на сервер
Репозиторий приватный, поэтому сервер получает «ключ только на чтение»:
1. На сервере: `ssh-keygen -t ed25519 -f ~/.ssh/deploy_key -N ""` затем `cat ~/.ssh/deploy_key.pub`.
2. На GitHub: репозиторий `PetrFedin/fur-erp` → Settings → Deploy keys → Add deploy key → вставьте строку, название `timeweb`, **галочку «Allow write access» НЕ ставьте** → Add key.
3. На сервере:
   ```bash
   cat >> ~/.ssh/config <<'CFG'
   Host github.com
     IdentityFile ~/.ssh/deploy_key
     StrictHostKeyChecking accept-new
   CFG
   cd ~ && git clone git@github.com:PetrFedin/fur-erp.git fur-erp
   cd fur-erp && git log --oneline | head -3
   ```
   Папка обязательно называется `fur-erp` (от этого зависит имя тома в скрипте копий).

## Шаг 7. Настроить секреты
```bash
cd ~/fur-erp
cp deploy/.env.prod.example .env
echo "DB: $(openssl rand -hex 16)"
echo "AUTH: $(openssl rand -base64 32)"
nano .env
```
В открывшемся файле впишите: `DOMAIN` (из шага 5), `DB_PASSWORD` (строка после «DB:»), `AUTH_SECRET` (строка после «AUTH:»), `ALLOW_REGISTRATION=false`. Сохранить: `Ctrl+O`, `Enter`, выйти: `Ctrl+X`.
Файл `.env` никому не пересылайте и в git не добавляйте (он в .gitignore).

## Шаг 8. Перенести данные с вашего ноутбука
Это делается на **ноутбуке**, не на сервере. Docker с базой должен быть запущен (`docker ps` показывает `fur-erp-db-1`).
```bash
cd /Users/petr/Documents/claude/fur-erp
docker exec fur-erp-db-1 pg_dump -U fur_erp --no-owner fur_erp | gzip > /tmp/fur_erp.sql.gz
tar czf /tmp/uploads.tgz -C uploads .
scp /tmp/fur_erp.sql.gz /tmp/uploads.tgz root@185.12.34.56:/root/
```

## Шаг 9. Первый запуск и загрузка данных (на сервере)
```bash
cd ~/fur-erp
docker compose -f docker-compose.prod.yml up -d db
sleep 15
gunzip -c ~/fur_erp.sql.gz | docker compose -f docker-compose.prod.yml exec -T db psql -U fur_erp -d fur_erp
docker compose -f docker-compose.prod.yml up -d --build
```
Первая сборка занимает 5–10 минут. Затем файлы документов:
```bash
docker run --rm -v fur-erp_fur_erp_uploads:/data -v /root:/in alpine sh -c "cd /data && tar xzf /in/uploads.tgz"
docker compose -f docker-compose.prod.yml restart app
```
Проверка состояния: `docker compose -f docker-compose.prod.yml ps` — все три сервиса (`db`, `app`, `caddy`) в статусе Up. Логи: `docker compose -f docker-compose.prod.yml logs -f app` (выход `Ctrl+C`).

## Шаг 10. Проверить сайт
1. В браузере откройте `https://<ваш DOMAIN>` — должна открыться страница входа (замок в адресной строке: HTTPS работает; сертификат Caddy получает сам в течение минуты).
2. Войдите тестовым пользователем (пароль есть у владельца). Проверьте: Сводка открывается, в «Сырьё» видны аукционы, в карточке закупки открывается документ (файл из загруженных).
3. Откройте `https://<DOMAIN>/register` — должно перекинуть на вход (регистрация закрыта).

## Шаг 11. Выдать доступ заказчику
1. Войдите владельцем → Настройки → Пользователи → добавьте сотрудника заказчика: email, имя, **роль** (для тестирования: «Наблюдатель» — только просмотр; «Администратор» — всё), одноразовый пароль.
2. Передайте заказчику: адрес сайта, логин, пароль **разными сообщениями**, и файл `docs/TESTING.md` (что и как проверять).
3. **Сменить или удалить тестового пользователя** `anna@qa-test.ru` с известным паролем: он есть в копии данных.
4. По желанию — дополнительный замок на весь сайт (пароль на входе в браузере): сгенерируйте хэш `docker run --rm caddy:2-alpine caddy hash-password --plaintext 'пароль'` и в `deploy/Caddyfile` добавьте перед `reverse_proxy` блок `basic_auth { имя ХЭШ }`; затем `docker compose -f docker-compose.prod.yml up -d caddy`. Рекомендуется, пока сайт открыт в интернет для теста: у входа нет ограничения числа попыток.

## Шаг 12. Резервные копии (обязательно)
Данные заказчика и ваши документы — на единственном диске сервера. Один раз настройте ночную копию:
```bash
cd ~/fur-erp
sh deploy/backup.sh          # проверка: в ~/backups/fur-erp появились db_*.sql.gz и uploads_*.tgz
crontab -e
```
В открывшемся файле добавьте строку (каждую ночь в 03:30):
```
30 3 * * * cd /root/fur-erp && sh deploy/backup.sh >> /root/backup.log 2>&1
```
Раз в неделю скачивайте копии на свой компьютер: `scp -r root@185.12.34.56:/root/backups/fur-erp ~/Backups/fur-erp-server`. В Timeweb можно также включить автоматические бэкапы всего диска сервера (платная опция) — рекомендуется. **Проверьте восстановление хотя бы один раз** (шаг 9 на тестовом сервере) — копия, которую не пробовали восстановить, не копия.

**Проверка восстановления (сделана 04.10.2026 на ноутбуке):** свежий дамп `fur_erp_20261004_201541.sql.gz` развёрнут в отдельную пустую базу `fur_erp_restore_test` командой `gunzip -c файл | docker exec -i fur-erp-db-1 psql -U fur_erp -d fur_erp_restore_test` — без ошибок; числа строк совпали с боевой базой (закупок 61, оплат 28, ТЗ 183, лотов 287, документов Drive 1108, цветов 24, позиций закупок 407, оплат производства 22). Пробная база после проверки удалена. Архив `uploads_*.tar.gz` содержит все 11 файлов из папки `uploads`. Пути файлов в базе относительные (`purchase-docs/…`), поэтому переносятся на сервер вместе с папкой. Повторяйте проверку после каждого заметного обновления.

## Обновление версии (после новых правок)
На ноутбуке: `git push` (как сейчас). На сервере:
```bash
cd ~/fur-erp && git pull && docker compose -f docker-compose.prod.yml up -d --build
```
Миграции базы применяются автоматически при старте приложения (в `docker-entrypoint.sh`).

**Правило: перед каждым обновлением версии — `sh deploy/backup.sh`** (копия базы и файлов за минуту; без неё откатиться некуда). Затем проверьте, нет ли в новых миграциях разрушающих операций:
```bash
sh scripts/check-migration-safety.sh      # «ОПАСНО: требуется бэкап и ручная проверка» — прочитайте указанную миграцию до `up -d --build`
```
После успешного обновления поставьте новую отметку: `ls prisma/migrations | tail -1 | cut -c1-14 > scripts/.migration-baseline`. Подробности про сохранность данных и восстановление: `docs/DATA-SAFETY.md`.

## Если что-то не работает
| Симптом | Что делать |
|---|---|
| Сайт не открывается | `docker compose -f docker-compose.prod.yml ps`; `… logs caddy` (проблемы сертификата/домена), проверить DNS и что порты 80/443 открыты (`ufw status`) |
| Бесконечный вход / «Configuration» | Проверьте в `.env` `DOMAIN` и `AUTH_SECRET`; после правки `.env`: `docker compose -f docker-compose.prod.yml up -d` |
| 500 после обновления | `docker compose -f docker-compose.prod.yml logs --tail=100 app` |
| Не грузятся документы | Файлы в томе не восстановлены (шаг 9, вторая часть) или файл больше 25 МБ |
| Закончилось место | `df -h`, `docker system prune -af` (не трогает тома), удалить старые копии в `~/backups` |

## Что не входит в эту инструкцию (на будущее)
- Письма и уведомления (в приложении их нет).
- Мониторинг доступности (бесплатно: uptimerobot.com — проверка адреса сайта каждые 5 минут).
- Ограничение числа попыток входа в самом приложении (сейчас — только дополнительный пароль Caddy из шага 11.4).
- Раздельные стенды «тест» и «боевой» (когда заказчик начнёт вести реальный учёт — поднимите второй сервер или второй набор контейнеров).

## Что хранится и безопасно ли
- На сервере — реальные финансовые данные закупок и производства. Сервер в РФ (Timeweb), доступ только по SSH-ключу, база не торчит в интернет, HTTPS обязателен.
- Для теста можно заменить реальные суммы обезличенными копиями — если нужно, это отдельная задача.
