# Реестр источников массива данных (11.11.2026)

Составлен по коду: для каждой таблицы Prisma посчитано, в скольких файлах она читается/пишется (экраны · lib · скрипты загрузки · Excel). Объёмы — локальная база на 11.11.
Цель массива: единая связанная база, куда загружается всё присылаемое, и из которой строятся все таблицы, отчёты, графики и Excel.

Условные обозначения: **В массив** — участвует в расчётах/экранах/отчётах; **Позже** — нужна, но данных пока нет или связь слабая; **Вне** — служебное, в массив не включается.

## 3. Выводы
1. Большинство звеньев уже есть как таблицы и активно используются; в массив их нужно связать ключами и сделать единым входом загрузки, а не создавать заново.
2. Два пробела по данным, не по схеме: **нет клиентов** (в базе 1 запись) и **нет отгрузок** (1 запись); их нечем наполнять, пока владелец не пришлёт файлы.
3. Отчётные данные (отчёт по размерам, прайс, бюджет, прогнозы) живут JSON-пачками: их надо разложить в таблицы со ключами и датой действия.
4. Таблицы-кандидаты на удаление/игнор: ShipmentPlanRow (нигде не читается), CalendarEvent, ProductionPlan* (пусты). Удалять только после доказательства, что от них ничего не зависит.
5. Ключи связи сейчас разнородны: `modelCode` (строка нормализованная), `acode+color+size` (строка), id в таблицах; цвет — то ColorRef.id, то строка. Нужен единый ключ изделия и таблица синонимов.
