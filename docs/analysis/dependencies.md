# Зависимости данных и дыры пересчёта (08.10.2026)

Принцип владельца: всё, что сведено, корректируется с нижних уровней и пересчитывается по связям; при расхождении — уведомление.
Уведомление уже есть: движок самопроверки `src/lib/integrity` (колокольчик в шапке, вкладка «Контроль → Самопроверка», плашки на карточках, `scripts/check-invariants.ts`).
Единая точка пересчёта — черновик `src/lib/integrity/recalc.ts` (`recalcAfterEdit(entity, id, ctx)`), **в формы не внедрена**.

## Цепочка «снизу вверх»
позиция закупки + расходы → стоимость закупки → лоты (цена единицы) → списания в ТЗ (по цене лота) → себестоимость ТЗ (снимок `totalCost`) → партия → склад готовой продукции / аналитика / Сводка.
Оплаты: платёж → закупка/аукцион → долг поставщику; оплата подрядчика → разнесение на ТЗ → оплачено по партии. Подтверждения (`verifiedAt`, `confirmed`) стоят поверх всего и должны сбрасываться при любой правке снизу.

## Что уже пересчитывается правильно
`syncCompletedOrderCost` после правки списаний/расходов завершённого ТЗ; `resetBy*` после правок закупок/ТЗ/оплат; переименование цвета/категории/аукциона каскадом меняет кэш-тексты в лотах, позициях, ТЗ, оплатах; пересчёт лота до первого списания.
