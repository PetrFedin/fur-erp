# Единый формат фильтров: анализ и план (07.10.2026)

Источник: аудит агента по коду `src/app/(app)/**` (только чтение). Полный список контролов по страницам — в таблицах ниже в сжатом виде.

## Что есть сейчас
- 20 страниц с фильтрами, около 95 фильтров (≈45 одиночных select, ≈20 текстовых, ≈12 чекбоксов, ≈25 чипов-ссылок).
- Мультивыбор только на `/analytics/products` и `/analytics/pricing` (9 полей, повтор параметра `fur=a&fur=b`) и в таблицах лотов (клиентский, не в URL, теряется при обновлении).
- Основа, на которую можно опереться: `src/components/filter-panel.tsx` (оформление), `analytics/_shared/filter-panel.tsx` (`MultiPick`), `lots/lots-filters.tsx` (`MultiSelect` с поиском), `src/lib/analytics-filters.ts` (самая зрелая схема параметров).

## Топ несогласованностей
1. Одно понятие — разные имена параметра: аукцион (`auction`, `auc`, в `/payments` — `q`), сезон (`season`, `s`), вид меха (`kind`, `fur`), модель (`model`, `m`), поиск (`q`, `dq`, `article`).
2. Один параметр — разный смысл: `vat` = ставка 20/22/mix в аналитике, но режим incl/excl в Сводке `/lots`; `m` = месяц / маркап / id модели; `model` = id изделия или тип записи журнала.
3. Сезон: в `/production`, `/plan`, `/calendar` — id, в аналитике — код.
4. Нельзя выбрать несколько значений (например «СП 05.25 и РП 05.25» вместе).
5. Два несовместимых мультивыбора (аналитический без поиска; лотовый не в URL).
6. Применение везде разное («Найти», «Применить», «Показать», «Пересчитать»; чипы применяются сразу).
7. Аукцион выбирается шестью способами.
8. Фильтры теряются при переходах (клик по чипу аукциона сбрасывает `q` и `material`; смена вкладки сбрасывает поиск).
9. Год ведётся тремя механизмами (cookie шапки, мёртвые `year`/`dyear` в `/documents`, `py` в аналитике).
10. Нет единой индикации (чипы активных фильтров, «Сбросить всё»); «Все» называется семью способами; пагинация тремя механизмами.
- Нет фильтров там, где нужны: `/payments`, `/purchases`, `/lots`, `/production`, `/articles`, `/shipments`, `/fittings`, `/verify`, списки `/suppliers` `/clients` `/users` `/materials`, справочники цветов и меха, `/supply-plan`, `/reconciliation`.

## Единый стандарт
- **Применение:** одна кнопка «Применить» (и Enter), «Сбросить всё» — ссылка на чистый путь. Мгновенно — только вкладки/вид, быстрые чипы и удаление чипа.
- **`<MultiSelectFilter>`** (`src/components/filters/multi-select-filter.tsx`): выпадающий список с поиском, пункт «Все» (очищает выбор), счётчики, «Выбрать показанные», «Сбросить», значение `none` («Без …»), режим `single` для одиночного выбора, работает без JS.
- **URL:** значения повтором параметра (`auction=А&auction=Б`; запятая не подходит — в названиях аукционов есть запятые). Канонические имена: `q`, `auction`, `pyear`, `fur`, `color`, `lotcolor`, `batch`, `status`, `verified`, `supplier`, `client`, `category`, `size`, `season` (код), `vat` (20/22/mix), `vatmode` (incl/excl), `model`, `material`, `from`, `to`, `docs`, `sort`, `dir`, `tab`, `view`, `page`, `limit`. Старые имена читаются как псевдонимы (`auc`, `py`, `lc`, `kind`, `s`, `nds`, `dq`, `cat`, `need`).
- **Хелпер `src/lib/filters/`:** `defineFilters` + `parseFilters`, `filterHref`, `activeChips`, `toWhere` — вместо `cleanSearch`, `one`, `many`, `dateStr` и 8 локальных сборщиков ссылок.
- **`<FilterBar>`:** заменяет оба `FilterPanel`; заголовки «Фильтры …» сохраняются (их проверяет e2e `filter-style.spec.ts`); на мобильном свёрнута: «Фильтры (N)» + чипы.
- **Варианты фильтров** грузит `getFilterOptions(orgId, year, keys)`: аукционы — `Purchase.auctionSession`; мех — `FurRef`; цвета — `ColorRef`; партии — `ProductionBatch`; сезоны — `Season`; модели — `ProductModel`; поставщики/заказчики/материалы — свои таблицы. Кэш — Map с TTL 30 с + инвалидация из server actions (как `getFurIndex`); `unstable_cache` не использовать, пока не прочитана документация Next 16.3.6 в `node_modules/next/dist/docs/`.

## Риски
- Закладки и ссылки на `?auction=`, `?batch=`, `?q=`, `?tab=`, `?view=` — закрываются псевдонимами.
- E2E (auction, drive-structure, live-check, mobile-edit, cleanup-upload, purchases, payments, filter-style, dashboard) завязаны на разметку чипов `a[href^="/lots?auction="]` и заголовки панелей.
- Общий год из шапки и cookie `vatDisplay`/`commission4Display` не должны смешиваться с фильтрами.
- Тяжёлые страницы `/lots`, `/production`.

## Критерии приёмки
1. На всех страницах один язык: `FilterBar`, «Применить», «Сбросить всё», «Все», чипы.
2. Мультивыбор для аукциона, меха, цвета, партии, статуса, сезона, категории, размера, заказчика, поставщика.
3. Единые имена параметров; старые ссылки работают.
4. Фильтры сохраняются при пагинации, смене вида и вкладки; ссылка воспроизводит выбор.
5. На 375 px панель свёрнута, без горизонтальной прокрутки.
6. Без JS форма работает.
7. Локальные сборщики и парсеры удалены.
8. Юнит-тесты хелпера и все e2e зелёные.
9. Итоги при том же выборе совпадают с до-миграционными при всех положениях шапки.
10. Время ответа `/lots`, `/production`, `/purchases` не хуже +10%.

## Решения владельца
1. Применение кнопкой (рекомендуется) или сразу.
2. Разделитель: повтор параметра (рекомендуется) или запятая.
3. Год в ссылках: только cookie или необязательное `?year=` (рекомендуется).
4. Сезон в URL: код (рекомендуется) или id.
5. Фильтры таблиц лотов аукциона: мгновенные клиентские или привязанные к URL по кнопке.
6. Добавлять ли «подтверждено / ждёт» в закупки, оплаты, ТЗ, лоты.
7. Нужны ли фильтры в коротких справочниках.

Фундамент: `src/lib/filters/index.ts` (defineFilters, parseFilters, filterHref, resetHref, activeChips, toWhere, псевдонимы), `src/lib/filter-options.ts` (getFilterOptions, кэш 30 с; точка подключения справочника аукционов — `loadAuctionFilterOptions`), `src/components/filters/filter-bar.tsx` и `multi-select-filter.tsx`; проверки — `npx tsx scripts/test-filters.ts`.

Поля вида (группировка, статус, маркап, база наценки) — controls с `state: true`: применяются сразу, не считаются фильтрами.
