# Ревизия 07: «Настройки», «Контроль» (verify, history, integrity), справочники

Дата: 2026-11-15. Только чтение кода, без запуска. Приоритет: В/С/Н (высокий/средний/низкий). Трудоёмкость: м/с/б (малая/средняя/большая).

## 1. Краткий вывод

1. Настройки по сути — 15 плиток-ссылок; 5 из них ведут за пределы `/settings` (материалы, поставщики, заказчики, склады, пользователи). Это нормально как «каталог», но у 6 плиток нет описания, а у двух справочников (цвета, категории) описания пустые.
2. Шесть справочников (цвета, категории, мех, признаки меха, аукционы, артикулы) устроены по одному шаблону: «не сопоставлено» → «добавить» → фильтр → таблица → карандаш с тремя формами. Шаблон хороший, но в каждом свои мелкие расхождения (статус, подсказки, кнопки), и в двух из них «ждёт подтверждения» дублируется бейджем, фильтром и кнопкой.
3. Главный пробел: таблица `DmCheck` (контрольные суммы единой витрины, 25+ проверок в `src/lib/mart/build.ts`) пишется при каждой пересборке, но **нигде не читается** (поиск по `src/` — только build.ts). Владелец не видит ни «цвет без пары в справочнике», ни «цены без изделия», ни «остаток без закупочной». Нужна вкладка «Данные» в «Контроле».
4. Цвет, не найденный в ColorRef, молча становится «каноном» как есть (`canonOf` в build.ts, origin = "auto"). Нет проверки и счётчика таких цветов; очередь «Не сопоставлено» в справочнике цветов смотрит на ТЗ/закупки/лоты, но не на отчёты и движения витрины.
5. Счётчики использования в справочниках (ТЗ, лотов, закупок) — три разных числа на цвет; витрина (изделия, остаток) в них не участвует. Пользователь видит «Цвет: 0 ТЗ, 0 лотов» и может удалить цвет, который нужен витрине.
6. «Контроль» — шесть вкладок (Задачи, Подтвердить, Документы, Сверка, История, Входящие), внутри «Сверки» ещё «Проверка данных» (интегритет, ~40 проверок). Для владельца это четыре разных места ответа на вопрос «всё ли сходится». Предлагаю один вход «Сходится ли» с вкладками-источниками.
7. «Подтвердить» перегружена: 4 вкладки × 4 фильтра состояния × поиск × 4 плитки итогов × подсказка на 5 абзацев × блок повторов × массовая очередь. Плитки дублируют бейджи вкладок.
8. Мёртвые/дублирующие адреса: `/integrity` и `/expense-categories` — только редиректы (оставить, но убрать из списков «also» в nav). Страницы «Роли» нет вообще: роли — выпадающий список в «Пользователях».
9. На iPad: иконка-карандаш 28 px, но с невидимой зоной 44 px (`.icon-btn::after`) — достаточно; плотные инлайн-формы и таблицы справочников на 820 px требуют проверки горизонтального скролла (Мех, Аукционы, Артикулы).

| Цены | `priceOrphans` (цены без изделия) | есть | показать со списком первых 20 |
| Зачёты | `shipmentOrphans` (зачёты без изделия) | есть | то же |
| Движения файла | `movementOrphans` | есть | то же |
| Закупочная | `noCostSold`, `noCostStock`, `noTz` (остаток без закупочной / без ТЗ) | есть | показать, ссылка на ТЗ |
| Лоты | `lotNoPurchase`, `lotQtyBalance`, `purchaseVsLots`, `usageVsMaterial` (лоты без закупки) | есть (если `chainRef`) | показать |
| Приход | `fileVsReport` (расхождение прихода файла и отчёта) | есть, статус info | показать как «справочно», с разницей в штуках |
| Платежи | `payOverAlloc` | есть | показать |
| Продано сверх прихода | `oversold` | есть | показать |
| В работе, бюджет | `inWork`, `planPcs`, `stockCostTz`, `stockCostReportEur` | info | показать мелким текстом «справка», не в красных |
| Мех / категория / артикул | — | **нет** | ДОБАВИТЬ: артикулы без кода продаж, цвета/виды меха в отчёте без пары |

Правила показа: сверху одна строка «Данные собраны: дата, N проверок, K не сошлось»; красным только `fail`, жёлтым `warn`, `info` — серым текстом; без полос; строки раскрываются списком конкретных записей (до 20). Каждая строка — ссылка на экран, где это чинится. Источник один — `DmCheck`, чтобы число в «Контроле» и в «Сверке» не расходилось с `/settings/import` (пересборка витрины после загрузки). Права — владелец и администратор.

Замечание по build.ts: ключи с пометкой `expected: 0` и `status warn` не отличают «ошибка данных» от «нормальный хвост»; для UI заранее нужна колонка `severity`/группа (сейчас только `status` и `label`) — малая правка схемы или маппинг по `key` в коде.

## 7. Число → где показано → откуда берётся

| Цена продажи артикула | `/settings/articles-ref` | ProductModel.sellingPrice — дубль «Изделий» |
| Заказано 845, Получено 637, Остаток 371 | «Контроль → Данные» (будет), аналитика | `MART_EXPECTED` vs суммы отчёта в build.ts (`ordered`, `received`, `stock`) |

## 8. Общие справочники в БД и связь со страницами
