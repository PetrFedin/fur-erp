Дата: 15.11.2026. Только чтение кода, ничего не менялось и не запускалось. Источники: `src/app/(app)/{purchases,lots,materials,raw-materials,lining,supply-plan,warehouses}/**`, `src/components/{fur-selection-total,fur-scope,raw-tabs,fur-source-nav}.tsx`, `src/app/(app)/dashboard/{raw-block,pay-tiles}.tsx`, `src/lib/{fur-table,fur-table-server,purchase-totals,auction-payments,lot-hammer,raw-stage-server}.ts`, схема `Dm*` в `prisma/schema.prisma`, `src/lib/mart/*`. Что видно только на экране (реальная ширина, перенос, касания) не проверялось: отмечено «проверить на iPad».
Обозначения: приоритет В/С/Н (высокий/средний/низкий), трудоёмкость М/С/Б (малая/средняя/большая).

## 1. Краткий вывод

1. Раздел состоит из двух «лиц» одних и тех же данных: «Закупки» (`/purchases`, суммы по документам) и «Сырьё» (`/lots`, суммы по лотам). Итоги сведены до рубля искусственной строкой «Округление», а не общим источником: это самая шумная и хрупкая часть раздела.
2. Ни одна страница раздела не читает витрину `Dm*`: `DmPurchase`, `DmLot`, `DmLotUse`, `DmPayment` собираются (`mart/chain.ts`), но используются только скриптом `mart-verify`. Все числа считаются заново из `loadFurLots` / `loadDashboard` / `purchase-totals` / `auction-payments`. Одно число имеет минимум 3-4 расчёта (см. раздел 7).
3. Страница `/lots` перегружена: 3 переключателя («Источник», «Строки по», карусель видов), панель фильтров на 8-10 полей, 6 плиток × 4 строки, «Динамика по годам», «Сверка», `AuctionCompare`, таблица на 12 числовых столбцов, 8 «i». Из этого владельцу нужны: плитки «Куплено / Использовано / Остаток», один переключатель источника, таблица.
4. Заголовок «Сырьё» + хлебные крошки «Сырьё › Мех» + вкладка «Мех» + заголовок плиток «Сырьё и оплаты — мех» + скрытый `h2 «Мех»` + заголовок таблицы «Динамика по сырью»: название одного и того же блока повторено 5 раз.
5. «Сводка по годам» (`/lots?tab=summary`) по сути пустая вкладка: ссылка на Главную и скрытые под `<details>` две таблицы с Главной. `summary-view.tsx` (502 строки), `summary-node-action.tsx`, `vat-sync.tsx` — мёртвый код: страница их не подключает.
6. Главная кнопка раздела расходится: на `/purchases` главная «+ Закупка меха», на `/lots` главная «+ Добавить материал» (справочник), а закупка стоит вторичной. Правило «одна главная кнопка» и логика нарушены.
7. Мастер партии (`/purchases/batch`) хорош по сути (3 шага + результат, черновик, сверка с документом), но подсказка «Загрузите документы пачкой» устарела: в коде «документы партии больше не прикладываются»; `/purchases/new` (старая форма) без входящих ссылок; в мастере 14 полей шапки, часть нужна редко.
8. Цена молотка в $ показана честно (только из расчёта лота, нет — «–»), но колонка молотка скрыта флагом `showHam = false`, а $-колонки «Ср. цена $» занимают 3 столбца из 12 при покрытии «n из N лотов»: шум, пока не у всех лотов есть $.
9. `/supply-plan` — это план поставок готовых изделий (артикул × месяц), а не сырья; уже скрыт из меню. `/raw-materials` и `/lining` — редиректы, их оставить как есть. `/warehouses` — справочник из одной-двух строк.
10. Подсказок «i» в разделе около 40 (из них 8 в одной таблице `fur-selection-total`); несколько — простыни из 2-3 абзацев с правилами, которые уже видны данными. Нарушение принципа «без текстового шума».
