# Ревизия интерфейса: «Продажи и остатки», аналитика, «Отгрузки и календарь», планы

Дата: 15.11.2026. Только чтение кода (ничего не запускалось). Участок: `src/app/(app)/sales/**`, `analytics/**` (изделия, цены, маржа; сырьё `analytics/raw` разбирает другой участок), `shipments/**`, `calendar/**`, `plan/**`.
Условные обозначения: приоритет В/С/Н (высокий/средний/низкий), трудоёмкость м/с/б (малая/средняя/большая). Решения: ОСТАВИТЬ, УБРАТЬ, УПРОСТИТЬ, ДОБАВИТЬ.

## 1. Краткий вывод

- «Продажи и остатки» перегружены не данными, а числом способов посмотреть одно и то же: пять вкладок, из них три показывают те же заказано / получено / продано / остаток (Сезоны, Динамика, Обзор), плюс «Маржа» в «Изделиях» как второе дерево тех же артикулов.
- Одного источника у числа нет. Плитки Обзора и итоги «Сезонов» берут штуки из отчёта (845 / 637 / 291 / 346), график, «Остатки», «Топ», «Движение», «Приёмки по датам» и «Маржа» (дерево) — из строк файла (659 при том же 291). Решение владельца 12.11 (868 / 659 / 291 / 368, `MART_EXPECTED`) в экранах ещё не применено: ни один экран не читает таблицы `Dm*`, их читает только сама сборка витрины (`src/lib/mart`).
- Маркап считается четырьмя способами и называется пятью именами: «Маркап» (вкладка Сезоны: (выручка+скидка) ÷ 110 ÷ SC EUR), «Наценка прихода» и «Наценка к ТЗ» (Маржа: розница ÷ себестоимость ТЗ в ₽), «Наценка» в «Движении» (прайс ÷ себестоимость ТЗ), «MU current» в каталоге, «Наценка к сырью» в «Ценах».
- Вкладка «Сезоны: заказ и продажи» — главная и самая тяжёлая: сводка из ~30 строк × 3 сезона + 6 групп показателей + дерево до размера + карточки + «Приход по месяцам». Нужна, но в 2 раза короче.
- Кнопки «Отчёт: продажи / поставки» и «Excel» в разделе «Продажи» недостижимы: они в шапке каталога, которая скрыта (`embedded`). Работают только на странице «Каталог».
- «Отгрузки и календарь»: страница `/shipments` считает список отгрузок, фильтры и итоги, но не показывает их (в JSX только вкладки и «Приёмки по датам»). Поставщик (SUPPLIER) видит пустую страницу: для него `feed = []`. Карточки отгрузок открываются только по прямой ссылке и из календаря.
- «План заказа», «Сезоны ТЗ», «Примерки» скрыты (`HIDDEN_MODULES`), в меню их нет. Код и запросы живые; кнопка «Календарь» → «План заказа» скрыта. Оставить скрытыми, ничего не развивать.
- Цели касания на iPad 820: кнопки календаря `h-8` (32 px, на телефоне 40, на ≥768 без `min-h-11`), ряд кнопок `h-7/h-8` в карточке отгрузки. Мелочь, но это прямое нарушение правила 44 px.
- Сколько вкладок нужно в «Продажах»: 3 вместо 5 (Сезоны · Обзор · Топ и залежи).

## 2. Раздел «Продажи и остатки» (`/sales`)

Общее: страница `sales/page.tsx` грузит `loadSalesInput` (строки файла `SalesReceiptLine` + цены + себестоимость ТЗ), `loadChain` (цепочка ТЗ), `loadDatamartStock` (внешняя витрина datamart: остатки на даты снимков, это НЕ наши `Dm*`), `tzAwaitSizes`, `loadReportSizesState` (отчёт «заказ и продажи» → `ReportSizeRow`). Внешний поставщик не допускается. Вкладка по умолчанию `report`, состояние в адресе (`?tab=&from=&to=&season=&c2=&fur=&cat=&q=&s=&g=&cols=&chain=`).
