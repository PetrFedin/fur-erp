# Ревизия 06: кабинет подрядчика, поставщики/заказчики, входящие, документы, чат, комментарии, история

Дата: 15.11.2026. Только чтение кода, ничего не менялось и не запускалось. Участок: `supplier/**` (10 страниц), `suppliers`, `clients`, `inbox`, `documents` (+`document-analysis`), `chat`, `comments`, `history`.
Обозначения: О = оставить, У = убрать, П = упростить, Д = добавить. Приоритет: В/С/Н. Трудоёмкость: м/ср/б.

## 1. Краткий вывод

1. Участок в целом осмысленный и без дублей чисел: цифры считает один расчёт (`calcAll` в `lib/supplier-calc`), показывают его везде одинаково. Витрина Dm*/vDm* здесь не используется вовсе (она про изделия/продажи) — это нормально.
2. Главная проблема не в числах, а в плотности: «Расчёт аукциона» (калькулятор в стиле Excel с формулами, параметрами, своими столбцами, контрольной разностью, форматами) и «Документы» (матрица покрытия + Drive-список + массовая загрузка + анализ) перегружены редкими функциями на первом экране.
3. Меню подрядчика — 9 пунктов, у владельца — 12. Цель владельца ≤6: у подрядчика достаточно 5 + «Ещё»; у владельца «Чат» и «Контроль» (вкладки Входящие/Документы/История) разумно оставить, но «Чат» уйти в «Ещё» при нуле непрочитанного.
4. Три дубля смысла: «Контроль» подрядчика (`/supplier`) пересказывает то, что уже есть в разделах «Сырьё», «ТЗ», «Отгрузки»; «Календарь» подрядчика почти повторяет общий календарь (+ отдельный блок «Аукционы» и таблица «По артикулам»); «Документы аукциона» в карточке сырья повторяют «Документы» владельца.
5. «Поставщики» и «Заказчики» — почти копии друг друга (123/123 строк, одинаковые карточки); карточки содержат оплаты/закупки, которые есть и в «Оплатах»/«Сырьё». Оставить как справочник + долг, остальное сжать.
6. «Чат»: много слоёв (4 статусных фильтра, фильтр темы, поиск, реакции, упоминания, Telegram, группы, привязка к записям). Для пары людей это избыточно: оставить список, поиск, «Ждут ответа»; реакции и «Группы/Закрытые» спрятать.
7. «Комментарии/История»: «Комментарии» — это инструмент разработчика (замечания к интерфейсу), он лежит в «История → Комментарии» и виден рядом с журналом изменений; журнал — нужен, но фильтров больше, чем нужно.
8. Нарушения принципов владельца точечные: лента этапов в «Сырьё» с левой серой полосой (`border-l-2`), обрезание (`truncate`) в ячейках календаря, текстовые пояснения-подзаголовки на каждой странице («Принимаем после проверки», «Записи видны в нашем календаре»).
9. Самый ценный быстрый выигрыш: убрать «Контроль» подрядчика как отдельный пункт (свернуть в плашку «Что от вас ждут» на «Сырьё»/«Аукционы»), свернуть «Параметры/Контрольная разность/Свои столбцы» калькулятора в «Дополнительно», разделить «Документы» на «Чего не хватает» и «Файлы Drive».

- Меню подрядчика (9): Аукционы `/supplier/auction-calcs`, Сырьё `/supplier/raw`, ТЗ `/supplier/tz`, Изделия `/articles`, Отгрузки `/shipments`, Календарь `/supplier/calendar`, Чат `/chat`, Справочники `/settings`, Контроль `/supplier`.

- Старые адреса `/comments`, `/document-analysis` — редиректы (оставить, но не показывать).
- ChatLink «Написать / Запросить» → `/chat?entity=Тип:id` встречается в: расчёте, ТЗ, карточке аукциона, календаре, карточке входящего (в виде «Уточнить у Веллмеха»). Один механизм, правильный.
- Внутри цепочки: Входящие → «Принять» → закупка-черновик или ТЗ (ссылки «Принято, создано»); подрядчик видит принятое в «Сырьё»/«ТЗ».
- Карточка поставщика → `/payments/s-id`, `/purchases/id`; карточка заказчика → `/payments/c-id`, `/production/id`.

## 5. Дубли и расхождения

| Что | Где повторяется | Решение |
|---|---|---|
| «Себестоимость / за шкуру / итого» | Расчёты аукционов, Сырьё (карточка), карточка аукциона, «Входящие» | числа одинаковы (`calcAll`), показывать полные только в расчёте, в остальных — одна цифра + ссылка |
| «Куплено / Оплачено / Долг» поставщика | `/suppliers/[id]`, Главная, «Оплаты → За сырьё» | долг — `loadSupplierDebt` (одинаков), «Куплено/Оплачено» на карточке считаются отдельно → риск расхождения; брать из одного источника |
| Контроль подрядчика | `/supplier` и разделы «Сырьё», «ТЗ», «Отгрузки», «Чат» | убрать как пункт меню, сводка плашкой |
| Календарь подрядчика | `/supplier/calendar` и `/calendar` | один календарь со слоями и правами; подрядчику — только его слой |
| Блок «Аукционы» календаря | `/supplier/calendar` и слой «Аукционы» | убрать отдельный блок |
| Документы аукциона | карточка сырья подрядчика и «Документы» владельца | допустимо, но ссылка на один источник (`PurchaseDocument` + `DriveDocument`) |
| Карточки «Оплаты/Закупки/ТЗ» поставщика/заказчика | и «Оплаты», «Сырьё», «Производство» | сократить до 5 строк + ссылки |
| Кнопки «Сохранить/Отправить» | вверху и внизу формы расчёта | оставить пару внизу |
| Кнопка «Загрузить Excel» | дважды в одной форме | оставить одну |
| «Комментарии» | кнопка в «Истории» и виджет везде | убрать кнопку из журнала |
| Подсказки-подзаголовки | почти каждая страница `<p text-sm text-neutral-600>` | убрать (принцип «без текстового шума») |

Расхождений в числах не найдено; риск только в «Куплено/Оплачено» (две независимые суммы).

## 6. Топ-10 упрощений

1. Убрать «Контроль» подрядчика из меню; сводка «что ждут» — плашкой на «Сырьё»/«Аукционы» (В/ср).
2. Меню подрядчика ≤6: Аукционы, Сырьё, ТЗ, Изделия, Чат, «Ещё» (Отгрузки, Календарь, Справочники) (В/м).
3. Калькулятор: «Параметры», «Столбцы/формулы», «Контрольная разность», «Вставить из Excel» — в «Для опытных» (В/ср).
4. Одна пара кнопок «Сохранить черновик / Отправить» вместо двух (С/м).
5. «Документы»: разделить на «Чего не хватает» (TodoSummary + плитки) и «Файлы Drive» (каталог); матрицу сократить до 5 колонок (В/ср).
6. «Сырьё» подрядчика: фильтры до 2, таблица лотов — склеить «Цвет+Размер», убрать «Счёт» при одном счёте, убрать левую полосу ленты этапов (С/ср).
7. Чат: убрать фильтр по теме, реакции, чипы «Группы/Закрытые»; Telegram — в «Настройки → Каналы» (С/ср).
8. «Комментарии» убрать из «Истории», оставить виджет с 2 режимами и фильтры списка до 3 (С/ср).
9. Поставщики/Заказчики: «Оплаты» и «Закупки/ТЗ» — по 5 строк со ссылкой «Все»; «Куплено/Оплачено» из `loadSupplierDebt` (С/ср).
10. Убрать текстовые подзаголовки и подсказки «i», повторяющие заголовок (Н/м).

Дополнительно по принципам владельца: снять `truncate` в ячейках календаря и `border-l-2` в ленте этапов; цели касания у ссылок-списков поднять до 44 px не только на `max-md`, но и на 820 px (iPad).

## 8. Число → где показано → откуда берётся

| Число | Где показано | Откуда берётся |
|---|---|---|
| Шкур, Итого ₽, Средняя за шкуру | Расчёты аукционов, Сырьё (карточка и аукцион), Входящие, карточка аукциона | `calcAll(payload)` (`lib/supplier-calc`): `qty`, `totalRub`, `totalRub/qty` |
| Остаток к оплате | расчёт, карточка аукциона, Сырьё | `calcAll.rest = totalRub − advance − interim` |
| За шкуру, ₽ по лоту; Сумма ₽ по лоту | таблица лотов «Сырьё» | `buildStatement(payload).lots[].unit/total` (только при единственном совпадении лота) |
| УПД без НДС (цена, сумма) | таблица лотов, заголовок аукциона | `PurchaseItem.unitPrice`, `subtotal` (`supplierRawRows`) |
| Курс, НДС | карточка аукциона, Входящие | `payload.header` (`rate`, `calcVatPct`) |
| PayChip «оплачено/частично» | Сырьё, расчёты, ТЗ, карточка | `loadSupplierPayData`/`groupPayInfo`/`tzPayInfo` — только проведённые (COMPLETED) оплаты подрядчика |
| «Принято на склад», этап, просрочка | Сырьё, Контроль подрядчика | `PurchaseItem/Purchase.status`, `SupplierRawStage`, `summarizeStages` |
| «Платёжный документ: есть/нет» | карточка аукциона | `paymentDocFlagsFor` (булев признак) |
| ТЗ «Изделий» | список ТЗ, Входящие | `payload.totals.qty` или `tzTotals(payload).qty` |
| Долг поставщику, Куплено, Оплачено | `/suppliers/[id]` | долг — `loadSupplierDebt`; «Куплено»/«Оплачено» — суммы на странице: `purchaseTotalInclVat`, платежи COMPLETED |
| Работа по ТЗ, Оплачено, Долг/Переплата заказчика | `/clients/[id]` | `loadClientDebt`, `orderWorkCents`, `allocatedCentsByOrder` |
| Число «на проверке» (бейдж «Входящие»), задач, «ждут подтверждения», «неполных комплектов» | вкладки «Контроль» | `loadControlCounts(org, year)` |

| Документы Drive (×N, «Привязан к») | «Документы» | `loadDocList`, `groupDocList` (DriveDocument) |
| Непрочитанные, «ждёт ответа» | «Чат», меню, «Контроль» подрядчика | `ChatRead.lastReadAt`, `awaitsMyAnswer`, `chatCounts` |
| Записей в журнале, «Кто/Что/Действие» | «История» | `AuditLog`, год не применяется |
| Открытых комментариев | «История → Комментарии» | `prisma.comment.count({ status: OPEN })` |
| Витрина Dm*/vDm* | — | на этом участке не используется |
