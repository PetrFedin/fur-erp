# Бесплатная ссылка для внешних тестировщиков (Render, один аккаунт)

Версия: 15.10.2026. Нужен ОДИН сервис: Render (render.com). Отдельные Neon, GitHub Actions, ghcr.io и токены не нужны. Работает без вашего MacBook. Обезличенная демо-база вшита в образ и загружается сама при первом запуске.

Что получится: адрес вида `https://fur-erp-demo.onrender.com`. При открытии браузер спросит общий логин и пароль («замок»), затем откроется страница входа в приложение, где у каждого тестировщика свой логин.

Важно: в репозитории лежит только обезличенная база (`deploy/demo/demo.sql.gz`: вымышленные контрагенты, суммы умножены на скрытый коэффициент, пользователи только `*@demo.mvst`). Рабочая база и ваши документы на Render не попадают.

---

## А. Регистрация и доступ к репозиторию

1. Откройте в браузере https://render.com и нажмите справа вверху **Get Started** (или **Sign in**, если аккаунт уже есть).
2. Нажмите кнопку **GitHub** («Sign in with GitHub») и войдите под своим аккаунтом PetrFedin. Если GitHub спросит разрешение, нажмите зелёную кнопку **Authorize Render**.
3. Если Render просит карту, выбирайте только бесплатные тарифы (Free). Для описанного ниже пути карта не нужна. Если карту требуют именно на этом шаге, остановитесь и напишите мне.
4. Репозиторий приватный, поэтому дайте Render доступ именно к нему: в Render нажмите **New +** (вверху справа) → **Blueprint** → в блоке «Connect a repository» нажмите **Configure account** (или «Configure GitHub App»). Откроется страница GitHub. В разделе **Repository access** выберите **Only select repositories**, в списке выберите **PetrFedin/fur-erp**, нажмите **Save**. Вы вернётесь в Render.

## Б. Создание стенда

1. В Render: **New +** → **Blueprint**.
2. В списке найдите **PetrFedin/fur-erp**, нажмите **Connect**.
3. Render прочитает файл `render.yaml` и покажет: сервис `fur-erp-demo` (Web Service, Free) и базу `fur-erp-demo-db` (PostgreSQL, Free). Название Blueprint можно оставить как есть.
4. Нажмите **Apply** (или **Deploy Blueprint**). Начнётся сборка.
5. Откройте сервис: слева **Dashboard** → **fur-erp-demo** → вкладка **Logs**. Первая сборка занимает 5–15 минут. Ждите, пока слева вверху рядом с названием появится зелёная надпись **Live**. В логах будут строки `[демо] дамп загружен: 5 пользователей, 61 закупок` и `замок слушает порт`.
6. Если сборка упала (красное **Failed**): откройте Logs, скопируйте последние 30 строк и пришлите мне. Самая частая причина: нехватка памяти при сборке на Free. Тогда нажмите **Manual Deploy** → **Clear build cache & deploy**; обычно со второго раза проходит.

## В. Адрес и пароль замка

1. **Адрес**: страница сервиса `fur-erp-demo`, под названием сервиса ссылка вида `https://fur-erp-demo-xxxx.onrender.com`. Кнопка копирования рядом.
2. **Логин замка**: `tester`.
3. **Пароль замка**: слева в меню сервиса **Environment** → строка `GATE_PASS` → значок глаза (**Reveal**) → скопируйте значение. Render создал его случайным.
4. Проверка: откройте адрес в окне инкогнито. Должно появиться окно «логин и пароль». Введите `tester` и пароль. Затем откроется страница входа. На странице входа НЕ должно быть списка демо-паролей и кнопки регистрации.

## Г. Что отправлять тестировщикам

Отправляйте тремя РАЗНЫМИ сообщениями (лучше разными способами или хотя бы с паузой):
1. Адрес `https://…onrender.com` и фраза «первое открытие может занять около минуты».
2. Логин и пароль замка (`tester` и значение `GATE_PASS`).
3. Личный логин в приложении: берите из файла `~/Backups/fur-erp/demo-logins.txt` (откройте в Finder: Переход → Переход к папке → `~/Backups/fur-erp`). Каждому тестировщику выдавайте роль с минимальными правами (не Владелец).
Файл с паролями никуда не пересылайте целиком.

## Д. Обновление, остановка, смена пароля

- **Обновить стенд новой версией кода**: автообновление выключено нарочно, чтобы стенд не менялся при каждом изменении. Сначала код попадает в GitHub (ветка main), затем в Render: сервис `fur-erp-demo` → справа вверху **Manual Deploy** → **Deploy latest commit**.
- **Обновить демо-данные**: заново создайте дамп (`sh scripts/make-demo-db.sh`, см. docs/DEPLOY.md), скопируйте свежий файл `~/Backups/fur-erp/demo/fur_erp_demo_<дата>.sql.gz` поверх `deploy/demo/demo.sql.gz` в репозитории, отправьте в GitHub и сделайте Manual Deploy. Дамп загружается только в ПУСТУЮ базу, поэтому сначала пересоздайте базу (раздел Е).
- **Приостановить**: сервис → **Settings** → внизу **Suspend Service**. Возобновить: **Resume Service**.
- **Удалить совсем**: сервис → **Settings** → внизу **Delete Web Service**; затем базу `fur-erp-demo-db` → **Settings** → **Delete Database**.
- **Сменить пароль замка**: сервис → **Environment** → `GATE_PASS` → **Edit** → введите новое значение (не короче 12 знаков) → **Save, rebuild, and deploy** (или **Save changes**). Старый пароль перестанет действовать сразу после перезапуска. Придумать пароль: в Терминале `openssl rand -base64 18`.
- **Убрать тестировщика**: самый простой способ — сменить пароль замка (он перестаёт попадать на сайт). Точечно: войдите владельцем в приложение и отключите пользователя в разделе пользователей, либо пересоздайте базу.

## Е. Если у вас уже был сервис fur-erp на Render

Старый сервис (`fur-erp.onrender.com`) чужой структуры не нужен, иначе будет путаница.
- Вариант 1 (рекомендую): удалите старый (сервис → **Settings** → **Delete Web Service**; старую базу тоже: **Delete Database**) и сделайте раздел Б заново.
- Вариант 2: оставить сервис и перенастроить: **Settings** → **Build & Deploy** → Runtime: **Docker**, Dockerfile Path: `./Dockerfile`, Branch: `main`, Health Check Path: `/healthz`, Auto-Deploy: **No**. Затем **Environment**: добавьте все переменные из `render.yaml` (таблица ниже), потом **Manual Deploy** → **Clear build cache & deploy**. Адрес сохранится. Этот вариант хуже: легко ошибиться, и Free-база старого сервиса может быть пустой или просроченной.

Переменные окружения (всё это уже записано в render.yaml, руками вводить нужно только при варианте 2):

| Переменная | Значение |
|---|---|
| `DEMO_BUILD` | `true` (без неё контейнер не стартует: защита от реальных справочников) |
| `DATABASE_URL` | Internal Database URL базы fur-erp-demo-db |
| `AUTH_SECRET` | случайная строка от 32 знаков (`openssl rand -base64 32`) |
| `GATE_USER` / `GATE_PASS` | `tester` / пароль замка от 12 знаков |
| `NODE_ENV` | `production` |
| `AUTH_TRUST_HOST` | `true` |
| `ALLOW_REGISTRATION`, `ALLOW_DEMO_LOGIN`, `ALLOW_ROLE_SWITCH` | все `false` |
| `UPLOAD_DIR` | `/tmp/uploads` |
| `NODE_OPTIONS` | `--max-old-space-size=192` |

## Ж. Ограничения бесплатных тарифов (честно)

Условия Render могут меняться; перед выдачей ссылки сверьтесь с https://render.com/docs/free.
- **Сон**: Free-сервис засыпает после 15 минут без запросов. Первое открытие после сна занимает около минуты (страница будет «думать»). Предупредите тестировщиков.
- **Память 512 МБ**: приложение с замком вместе занимают около 400 МБ (замерено локально на демо-данных: приложение около 315 МБ + замок около 70 МБ при открытии дашборда, лотов, закупок, сверки). Запас небольшой. Если сервис перезапускается с «Out of memory», уменьшите `NODE_OPTIONS` до `--max-old-space-size=160` или перейдите на платный тариф Starter (около 7 долл. в месяц).
- **База Free**: по условиям Render на момент написания бесплатная PostgreSQL живёт 30 дней, после чего её нужно пересоздать (она удаляется после короткого льготного периода; в кабинете за несколько дней до этого приходит письмо). Размер ограничен 1 ГБ, наши данные занимают менее 5 МБ.
- **Как пересоздать базу**: **Dashboard** → база `fur-erp-demo-db` → **Settings** → **Delete Database**; затем **Blueprints** → ваш Blueprint → **Manual Sync** (создаст новую базу и пропишет `DATABASE_URL`); потом сервис → **Manual Deploy** → **Restart**/Deploy. Демо-дамп загрузится заново автоматически, все изменения тестировщиков при этом пропадают.
- **Файлы**: загруженные тестировщиками файлы хранятся во временной папке и пропадают при каждом перезапуске. Для демо это нормально.
- **Лимит часов**: бесплатных часов работы в месяц хватает на один сервис (около 750).
- **Запасные варианты**: Koyeb, Fly.io (нужна карта, ограничения похожи), Railway (пробный кредит), либо недорогой VPS с `docker-compose.prod.yml` (docs/DEPLOY.md). Вариант с отдельной базой Neon (0,5 ГБ, засыпает через 5 минут простоя): `DATABASE_URL` из Neon достаточно задать в Environment сервиса вместо базы Render и убрать блок `databases` из render.yaml; дамп загрузится сам.

## З. Чек-лист безопасности перед выдачей ссылки

1. Открыть адрес в инкогнито: без пароля замка страница не открывается (окно логина/пароля).
2. Адрес `…/healthz` отвечает `ok` без пароля (это нормально, больше ничего не раскрывает).
3. После замка на странице входа нет подсказок с паролями и нет ссылки «Регистрация».
4. В Environment: `ALLOW_REGISTRATION`, `ALLOW_DEMO_LOGIN`, `ALLOW_ROLE_SWITCH` = `false`; `DEMO_BUILD` = `true`.
5. Войти ролью Поставщик: не видно чужих закупок и данных других ролей.
6. Названия контрагентов в приложении вымышленные (не Меркури, не ВеллМех и т. п.). Если встретили настоящее название, не выдавайте ссылку и напишите мне.
7. Ссылку и пароль замка отправлять разными сообщениями (раздел Г).

### Что обезличивается при демо-сборке и что остаётся

При `DEMO_BUILD=true` Dockerfile запускает `node scripts/demo-static-data.mjs`, который (1) заменяет вшитые JSON пустыми заготовками и (2) через `scripts/demo-sanitize.mjs` подменяет в `src/` реальные реквизиты (ИНН, КПП, счета, банк, адреса, подписанты, договоры №1605/№2502), названия компаний («Меркури Мода», «ВеллМех»), обезличивает Word-шаблоны ТЗ (позиции, лоты, цены, подписанты, свойства файла), примеры и подсказки расчётов (`calc-presets.json`), вырезает каталог задач и решений по долгу (`task-docs-catalog.ts`), счета-черновики с суммами (`supplier-debt.ts`) и тексты «известных случаев» (`integrity/known.ts`, `overpay-notes.ts` и др.). Общий признак демо в коде: `src/lib/demo-mode.ts`. Проверка: `npx tsx scripts/test-demo-sanitize.ts [папка с собранной демо-сборкой]`.

Чек-лист (делать при каждой выдаче новой демо-сборки):
1. Репозиторий `PetrFedin/fur-erp` остаётся ПРИВАТНЫМ: в исходниках (вне демо-образа) лежат реальные реквизиты, договоры, Word-шаблоны, пресеты и миграции с номерами договоров. Демо-образ их не содержит, но сам код — да.
2. После изменений в `src/` с новыми реквизитами, фамилиями или текстами из переписки добавить подмену в `scripts/demo-sanitize.mjs` (и запрещённую строку в `scripts/test-demo-sanitize.ts`) и прогнать тест на свежей демо-сборке.
3. Реальные данные БД закрывает `make-demo-db` (названия, ИНН, суммы с коэффициентом, пользователи `*@demo.mvst`); пересоздавать дамп при каждой смене схемы данных.
4. Остаётся осознанно: слово «Веллмех» как название роли/кабинета подрядчика (в базе «Веллмех-демо»), «ЦУМ» как подпись нашей стороны, «Коптево» как название склада приёмки (завязаны на логику), публичные названия аукционных домов, миграции `prisma/migrations/*contractors*` (номера договоров, показываются никому).
