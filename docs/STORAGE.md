# Хранилище файлов (этап 7)

Все загруженные файлы — документы Drive и закупок, фото артикулов и примерок, вложения чата и входящих —
читаются, пишутся и удаляются только через `src/lib/storage.ts`. В базе лежит относительный путь
(`drive-docs/<организация>/<uuid>.pdf`), одинаковый для обоих вариантов хранения.

| `STORAGE` | Где файлы | Когда |
|---|---|---|
| не задан / `local` | папка `UPLOAD_DIR` (по умолчанию `./uploads`) | Mac владельца, тесты |
| `s3` | бакет S3 (Yandex Object Storage и др.) | Render и любой облачный сервер |

Фото презентации FW27 (`uploads/fw27`) идут мимо хранилища — отдельная задача.

## Переменные для S3

| Переменная | Значение | Секрет |
|---|---|---|
| `STORAGE` | `s3` | нет |
| `S3_BUCKET` | имя бакета, например `fur-erp-docs` | нет |
| `S3_ACCESS_KEY_ID` | идентификатор статического ключа | да |
| `S3_SECRET_ACCESS_KEY` | секретный ключ | **да** |
| `S3_ENDPOINT` | `https://storage.yandexcloud.net` (по умолчанию) | нет |
| `S3_REGION` | `ru-central1` (по умолчанию) | нет |
| `S3_PREFIX` | общий префикс ключей, например `demo/` — чтобы демо и рабочая система не смешивались в одном бакете | нет |
| `S3_FORCE_PATH_STYLE` | `true` только для MinIO | нет |

## Подключение Yandex Object Storage — по шагам

1. **Платёжный аккаунт.** console.yandex.cloud → «Биллинг» → создать платёжный аккаунт (карта или договор на юрлицо).
   Без него бакет не создаётся. Бесплатный объём — см. yandex.cloud/ru/docs/storage/pricing, раздел «Бесплатное использование».
2. **Бакет.** Консоль → каталог (по умолчанию `default`) → «Object Storage» → «Создать бакет»:
   - имя: `fur-erp-docs` (латиница, уникально во всём Yandex Cloud — если занято, добавьте суффикс);
   - **доступ на чтение объектов: ограниченный**, на чтение списка — ограниченный, к настройкам — ограниченный;
   - класс хранилища: стандартное; максимальный размер — можно не задавать.
3. **Сервисный аккаунт.** Консоль → «Сервисные аккаунты» (в том же каталоге) → «Создать»:
   имя `fur-erp-storage`, роль **`storage.editor`**.
4. **Ключ доступа.** Открыть этот сервисный аккаунт → «Создать новый ключ» → «Создать статический ключ доступа».
   Окно покажет **идентификатор ключа** и **секретный ключ** один раз — сразу перенесите их в Render (шаг 5)
   или в менеджер паролей. В чат и в файлы репозитория ключ не вставлять.
5. **Render.** dashboard.render.com → сервис `fur-erp` → «Environment» → «Add Environment Variable» — по строке из таблицы выше:
   `STORAGE=s3`, `S3_BUCKET`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY`, `S3_PREFIX=demo/` (для демо).
   «Save, rebuild, and deploy» — Render перезапустит сервис с новыми переменными.
6. **Проверка.** В логах Render после старта: `[storage] S3: бакет fur-erp-docs, объектов N`.
   Ошибка ключа или имени бакета видна там же строкой `[storage] S3 недоступен при старте: …` — сервер при этом работает,
   файлы показываются как «не прикреплён».

## Перенос уже имеющихся файлов

Один раз перед включением `STORAGE=s3` (и повторно — запуск ничего не удаляет и пропускает уже перенесённое):

```bash
S3_BUCKET=fur-erp-docs S3_ACCESS_KEY_ID=… S3_SECRET_ACCESS_KEY=… \
  node node_modules/.bin/tsx scripts/storage-sync.ts --dry-run    # что будет перенесено
S3_BUCKET=fur-erp-docs S3_ACCESS_KEY_ID=… S3_SECRET_ACCESS_KEY=… \
  node node_modules/.bin/tsx scripts/storage-sync.ts              # перенос
```

Переменные удобнее положить в `.env` (он не в git) и запускать с `--env-file=.env`.
На демо Render файлов владельца нет (обезличенная база) — для него перенос не нужен, бакет наполняется загрузками посетителей.

## Откат

Убрать `STORAGE` (или `STORAGE=local`) — приложение снова читает папку `UPLOAD_DIR`. Файлы в бакете остаются.
Загруженное за время работы в S3 в папку само не вернётся — при откате его нужно скачать из бакета.

## Проверки

- `scripts/test-storage.ts` — договор хранилища для папки и S3 (S3-часть — при `S3_TEST_ENDPOINT`, в CI — MinIO).
- `scripts/storage-sync.ts --dry-run` — сколько файлов ещё не в бакете.
