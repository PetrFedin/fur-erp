**Ответ на вопрос про витрину.** `refreshMartInBackground` вызывается только после загрузки Excel и отката (`import/actions.ts:52,65`) и из `margin-server.ts:104` при состоянии «stale». Справочники цветов, категорий, меха, аукционов, а также закупки, ТЗ, лоты, платежи, приём входящих, решения владельца пересборку не запускают. Влияют ли они на результат витрины:
- **Цвета — влияют.** `buildMart` строит ключ изделия `skuKey` из «канонического» цвета `canonOf` (`mart/build.ts:63-67, 204`) по `ColorRef`; цвет без пары молча становится каноном «как есть» (origin `auto`, `:67`). Переименование/слияние цвета меняет канон и ключи.
- **Но устаревание не замечается:** `martFreshForReport` (`mart/read.ts:19-31`) смотрит только на `SystemState` (отчёт, прайс, журналы), `SalesReceiptLine` и `DmLoad`; на `ColorRef.updatedAt` не смотрит. Сейчас экраны читают из витрины лишь итоги сезонов (`martSeasonTotals`, суммы по сезону и классу), которые от цвета не зависят — видимого эффекта нет. Как только на витрину переведут блоки по цвету/изделию (в плане `MIGRATION-STATUS.md`), правка справочника цветов будет давать расхождение молча.
- **Категории.** В `build.ts` нет обращений к `CategoryRef` (поиск `category|cat1` даёт только колонки `DmSku`); на витрину категории не влияют напрямую. Мех, аукционы, признаки — тоже (в `build.ts` нет `furRef`/`auction`); аукцион попадает в `DmPurchase` из закупки, а не из справочника (не проверено построчно).
