## 1. Назначение и роли

**Главная** (`src/app/(app)/dashboard/page.tsx`) — витрина всего приложения: Активы (мех + изделия на стоке), Расходы (оплачено / к оплате), Сырьё, Динамика по годам и по сырью, Состав цены меха, Производство (выпуск, себестоимость), Продажи и остатки. Корень `/` редиректит сюда (`src/app/page.tsx:6`). Сюда же ведёт отказ в правах: `requireRole` → `/dashboard?error=forbidden` (`src/lib/session.ts:96`, баннер `page.tsx:107-111`).
**Схема работы** (`/scheme`) — онбординг «как ходят данные»; в меню отдельного пункта нет: страница лишь «also» у «Главной» (`src/components/nav-links.ts:4`), единственный вход — ссылка «→ Схема работы» в шапке Главной (`page.tsx:99`).
**Cashflow** (`/cashflow`, `src/app/(app)/cashflow/page.tsx`) — оплаченные деньги по статьям × месяцам и выручка, чистый поток, работа подрядчика на единицу. Отдельный пункт меню (`nav-links.ts:6`). `/payments/cashflow` — только редирект (`payments/cashflow/page.tsx:6`).

**Роли.** В `src/lib/access.ts` нет ключей для Главной, Cashflow и Схемы. Доступ — только `requireSession()` без `allowSupplier`: внешний поставщик (`SUPPLIER`) редиректится в `/supplier` (`session.ts:87`), все остальные роли (`OWNER, ADMIN, PURCHASER, WAREHOUSE, TECHNOLOGIST, ACCOUNTANT, VIEWER`, `prisma/schema.prisma:253-263`) видят всё, включая долги, оплаты, выручку и Cashflow. Меню фильтруется по роли только для «Чата» (`nav-links.ts:47`). Серверные действия Cashflow (`cashflow/actions.ts:11,35`) и `loadProductionDrill` (`dashboard/actions.ts:21`) тоже проверяют лишь вход. Это вопрос владельцу (см. §6.2): нужен ли кладовщику и наблюдателю доступ к деньгам.
В `page.tsx:66,68,69` остались ветки `role === "SUPPLIER" ? null`: недостижимы, потому что поставщика редиректит `requireSession` (мёртвый код).

## 2. Карта экрана «Главная»

Порядок блоков в разметке: шапка → дата данных → баннер целостности → «Фильтры сводки» → **Активы** → **Расходы** → [FurScope: **Сырьё**, **Динамика по годам**, **Динамика по сырью**, **Состав цены меха**] → [SeasonScope: панель «Сезон», **Производство**, **Продажи и остатки**] (`page.tsx:87-171`).

### 2.1 Как формируется страница (поток данных)

1. `page.tsx:59-63`: год из cookie (`getYearFilter`, `src/lib/year-filter.ts`), режим 4 % из cookie, фильтры из URL (`parseDashFilters`, `src/lib/dashboard-calc.ts:34-41`) → **`loadDashboard(org, year, f, c4)`** (`src/lib/dashboard-data.ts:310-898`, обёртка с кэшем запроса `:901`) — единый загрузчик для сырья, оплат, долга, ТЗ.
2. `page.tsx:64`: `priceComposition(org, d)` (`src/lib/price-composition-server.ts:38`) — состав цены меха (считается всегда, хотя блок свёрнут по умолчанию, `page.tsx:159`).
3. `page.tsx:66`: `loadSalesBlock(org, c4, year, f.fur)` (`dashboard/sales-block-data.ts:545-555`) — строки продаж/прихода (`SalesReceiptLine`, `src/lib/sales-server.ts:21`) + размеры отчёта (`loadReportSizes`, `src/lib/margin-server.ts:50`, JSON-состояние) + прайс (JSON-состояние) + себестоимость моделей из ТЗ.
4. `page.tsx:68`: `loadReportSeasonTotals(org)` (`margin-server.ts:90-127`) — **единственное место всего Главной/Cashflow, где читается витрина**: если `martFreshForReport` = «fresh» (`src/lib/mart/read.ts:20-30`), числа берутся из `DmSkuSeason`+`DmSku` (`martSeasonTotals`, `read.ts:35-51`); «stale» — запускается фоновая пересборка и берётся старый расчёт из отчёта (`loadReportSeasonTotalsLegacy`, `margin-server.ts:110-124`); «absent» (витрины нет, например демо-стенд — `read.ts:19`) — старый расчёт.
5. `page.tsx:69`: `loadDataAsOf` (`src/lib/data-as-of.ts`) — даты загрузки продаж/прихода/отчёта (`SalesReceiptLine.importTag`, `SystemState`).
6. Всё вызывается **последовательно** (`await` подряд), хотя `loadSalesBlock`, `loadReportSeasonTotals`, `loadDataAsOf` не зависят от `d` (см. проблему П-14).
7. В браузере (после показа) блок «Производство» дозагружает ТЗ серверным действием `loadProductionDrill` (`dashboard/actions.ts:20-43`, `loadDrillOrders` в `dashboard-data.ts:188-259`): вызывается при монтировании тремя клиентскими компонентами отдельно — `useDrill` (`averages.tsx:52-63`, из `ProductionBlock`), `ProductionTable` (`production-table.tsx:152-156`), позже `ProductionModal` (`production-modal.tsx:69`). Серверный кэш на 15 с (`actions.ts:12,28-30`) гасит повтор.

## 4. Связи и согласование чисел

### 4.1 От чего зависит Главная и что от неё зависит

Зависит от: «Оплаты» (`loadPaymentsOverview/Left`, `loadDebtInputs`), «Закупки» и «Сырьё» (`loadFurLots`), «Производство» (`loadOrderRows`, списания, партии), «Продажи» (`SalesReceiptLine` + отчёт и прайс из «Загрузки данных»), «Настройки» (справочники меха, цветов, категорий, аукционов), витрина (итоги сезонов).

Инвалидация: `integrity/recalc.ts` перечисляет `/dashboard` почти везде, но **ни разу не `/cashflow`** (grep пуст) — после правки платежа клиентский кэш Cashflow сбрасывается только перезагрузкой (низкая важность: страница динамическая, `cookies()`).
