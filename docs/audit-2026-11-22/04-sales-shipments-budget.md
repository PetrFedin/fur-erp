## 4. Связи с другими разделами и расхождения чисел

### 4.1 Откуда берутся «заказано / получено / продано / остаток»

В файлах отчёта владельца есть **три разных набора итогов**:

| Набор | Заказано | Получено | Остаток | Где фигурирует |
|---|---|---|---|---|
| Сезонные блоки отчёта (FW25/26 + SS26 + FW26/27) | 845 | 637 | 346 (= 637 − 291) | эталон по решению 16.11 (`mart/build.ts:22-26`, `MIGRATION-STATUS.md:9`); плитки `/sales` без фильтров, «Сезоны», Главная, «Производство», Cashflow |
| Итоговые колонки TTL того же листа Report | 881 | 668 | 371 | `TTL-VS-SEASONS-2026-11-12.md:3`; вариант «TTL» владельцем не выбран |
| Строки файла «поступления и продажи» | 868 | 659 | 368 (= 659 − 291) | график и дерево «Обзора», «Остатки», «Топ», «Движение», «Приёмки по датам»; витрина в режиме `MART_RECEIPTS_FROM_FILE=1` (`mart/build.ts:25,104`) |

Продано товара сезона = 291 во всех источниках.

Причина 659 против 637 (по `OPEN-QUESTIONS-2026-11-12.md`, вопросы 1 и 2): 25 шт. есть в файле прихода и отсутствуют в сезонных блоках отчёта (MH-02: 9+5+5 шт.; MGL-01 NATURAL: 6 шт.; поступили 09.02–04.03.2026 с пометкой FW 25/26), плюс расхождения на 1–3 шт. внутри моделей в обе стороны, итого +22 (файл 659 против отчёта 637). Заказано 868 против 845: +23, потому что у закрытых сезонов заказано берётся равным получено (`mart/build.ts:185`, `confOf`; `OPEN-QUESTIONS-DETAILED-2026-11-13.md:9`).

**Важная оговорка**: «637» на экранах не является чистым значением отчёта. `loadReportSizes` подменяет «получено по FW26/27» приходом из файла (`margin-server.ts:51-79`, `withOurFw26Delivered`): по `TTL-VS-SEASONS…md:20` в файле FW26/27 = 305, в блоке отчёта 304. Чистое значение отчёта без подмены я не вычислял (не проверял); `scripts/mart-verify.ts` сверяет с константой 637.

Ветвление источника внутри экрана `/sales` (`sales-view.tsx`):
- `orderFree` (`:117`): нет дат, Категории 2, меха и поиска → «заказано» и «получено» **из отчёта** (`orderedByReport`, `receivedByReport`, `sales-section.ts:306-312`); иначе **из строк файла**.
- `isPlain` (`:106`) и `stockEff` (`:121`): остаток «получено − продано» по отчёту при отсутствии любого фильтра, иначе нарастающий итог по файлу.
- `ovl` (`:128-133`): окна плиток переопределяются по отчёту, если `winRep`.
- Следствие: стоит выбрать любой фильтр (в том числе год из ссылки с Главной: `salesHref`, `sales-block-data.ts:215`), и «Получено» меняет источник с отчёта на файл. Подпись об этом есть только в «i».

Главная делает то же независимо: `useRep` (`sales-block-data.ts:353`) и `useRepTree` (`:302`): отчёт только при `year === "all"` и без фильтра меха. Поэтому на Главной с выбранным годом «Получено» тоже переключается на файл.

### 7.2 Переключатели режимов

Нужны ли на каждом экране? **Нет.**
- `/sales`: оставить только «Цены: с НДС / без НДС» (одна кнопка в шапке; убрать `?vat=` из адреса). «Год» не нужен (есть сезоны и период). «4 % к сырью»: либо убрать с `/sales` и показывать «с 4 %» всегда (как строится витрина, `mart/build.ts:51`), либо хранить в витрине обе себестоимости. ₽/€ убрать.
- `/shipments`, `/calendar`, `/budget*`, `/plan`, `/supply-plan`: режимов не показывать (на `/shipments` и `/calendar` они не действуют; бюджет имеет собственные параметры версии).
- Для демонстрации достаточно НДС на «Продажах» и «Приёмках» в режиме «Деньги».

### 7.3 Отгрузки и календарь

- Отгрузки: один экран «Отгрузки»: таблица (название, дата, подрядчик, партия, плановые/принятые/не принятые, статус) + карточка с приёмкой и итогом. «Приёмки по датам» перенести в «Продажи → Обзор». Данные: `Shipment*`; сверка зачётов ЗИ — из `DmShipmentLine` после сопоставления цветов. Для демо достаточно одной отгрузки с примеркой, приёмкой и накладными ЗИ.
- Календарь: 3 вида (Месяц, Список, Стадии); слои по умолчанию — аукционы, сырьё Веллмеха, окончания ТЗ; одна форма события. Данные те же (`CalendarEvent`, `Auction`, `SupplierRawStage`, ТЗ).

### 7.4 Бюджеты и прогнозы

- `/budget`: одна таблица «Документы» (тип: Бюджет / Прогноз сырья / Budget PCS / План 2027; сезон; итог; изменён кем и когда); «Сравнить версии».
- Редактор бюджета: «Сохранить» и «Загрузить из файла» на виду, остальное в меню «Ещё»; три плитки итогов; одна таблица «Сводка/Детально».
- Для демо достаточно: один утверждённый бюджет, один черновик, прогноз «Сырьё на остаток FW26», один Budget PCS. `/budget/plan27` оставить, если владелец им пользуется; иначе скрыть до решения (П22, П30).
- Витринные таблицы `DmPlanLine`/`DmPlanParam` подключать только после исправления подсчёта дублей по сценариям и после того, как каждый экран прочитает один сценарий (сейчас строятся все документы `budget-pcs:*`).
