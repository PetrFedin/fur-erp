# Проверка: входит ли подкладка в стоимость ТЗ в базе (пункт 2 apply-drive-open-items.ts)

Источники: ТЗ-приложения Google Drive «мех» (прочитаны все 14 файлов целиком) и боевая БД (только SELECT).
Скрипт: `scripts/apply-drive-lining.ts`.

## Как устроены документ и база
* Итог ТЗ в документе = сырьё + подкладка + работа (проверено арифметически по каждому из 14, см. таблицу).
* В БД у этих ТЗ: расходов `ProductionExpense` нет (работа не заводилась), списаний «Подкладочная ткань…» нет ни у одного из 14
  (у 66 других ТЗ есть), `totalCost = materialCost = Σ списаний сырья`. То есть БД = сырьё без подкладки и без работы.
* Для документов 2026 цены сырья в БД ниже документа на 4,00% / 5,73% (наценка 4% в базе не хранится), подкладка в документе
  1 854,66 ₽/м без НДС = 2 140 / 1,2 × 1,04 — в базе то же без наценки = 2 140 ₽/м (цена лота УПД №109).

## «Круглые» суммы ТЗ 80 / 81 / 85
Документ (ПРИЛОЖЕНИЕ 80/81/85) явно разделяет: «Общая стоимость шкур» 600 000 / 500 000 / 250 000 (= 60 / 50 / 25 шкур × 10 000 ₽, лоты 300302 и 5020)
и отдельной строкой «подкладочная ткань № 2» 17 976 / 10 700 / 5 350; «Итого» по блоку «Заказчик передал» = 617 976 / 510 700 / 255 350.
Значит 600 000 / 500 000 / 250 000 — только шкуры, подкладка в них НЕ входит; в БД эти суммы = Σ списаний шкур. Списывать подкладку можно.

## Вердикт
Для всех 14 ТЗ подкладка в БД не учтена, двойного счёта нет: пункт 2 безопасен. Единственное условие — не запускать пункт 2
`apply-drive-open-items.ts` после `apply-drive-lining.ts` (у него другой тег, повторного списания он не заметит): применять либо один, либо другой
(`apply-drive-open-items.ts --only 1,3,4,5` + `apply-drive-lining.ts`).

Что не изменилось из исходного п.2: «…/130» (Спец. №13), «шерсть/альпака/шёлк», ТЗ без номера ткани — не списываются (нет склада/документа).

## Нюанс политики цены (решение владельца, без блокировки)
Часть старых ТЗ (59, 61, 78, 79, 86, 87, 90, 101…, 117) уже списаны по 2 175,67 ₽/м (= 2 140 × 1,22/1,20), а новые строки идут по цене лота 2 140 ₽/м
(как в документах «без 4%»: «подкладочная ткань … 2140»). Для 14 ТЗ это соответствует документам.

## Проверка на scratch-копии боевой БД (fur_erp_lin, удалена)
DRY-RUN → `--apply` (14 списаний, 13 пересчётов завершённых ТЗ, 107 записей журнала) → повторный `--apply` («уже учтено» ×14, 0 записей) →
`--rollback --apply`: хеши остатков лотов, ТЗ (стоимости), остатков готовой продукции и счётчики движений/списаний после отката совпали с исходными.
Отрицательных остатков 0 → 0; новых расхождений «получено − выбыло ≠ остаток» и «списания ≠ движения» нет.
Остатки подкладки: №41 80,15 → 44,35; №37 56,55 → 36,15; №2 44 → 28,1; №24 23,3 → 21,7 (всего −73,7 м; +157 718 ₽ к стоимости 13 завершённых ТЗ + 5 136 по ТЗ 166).
