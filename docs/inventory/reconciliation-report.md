## Методика и запросы

Подключение: `docker exec fur-erp-db-1 psql -U fur_erp -d fur_erp` (только SELECT). Правила расчёта взяты из кода: src/lib/purchase-summary.ts, purchase-totals.ts, auction-payments.ts, batch-stats.ts, commission4.ts, app/(app)/dashboard/page.tsx.

- **[Q-лист]** — «лист сводки» (позиция закупки): `FROM "Purchase" p JOIN "PurchaseItem" i ON i."purchaseId"=p.id JOIN "RawMaterial" rm … LEFT JOIN "RawMaterialLot" l ON l.id=i."lotId" WHERE p.status<>'CANCELLED'`; год = `extract(year from p."orderDate")`; цена лота = `i.subtotal*p."exchangeRate"*(1+i."vatRate"/100)`; полная стоимость = `l."totalCost"` (если есть лот), иначе `costPlan.unitCostInclVat*quantity`, иначе цена; без НДС = `(l."materialCostExclVat"+l."expenseCostExclVat")*quantity` (если обе 0 и `unitCost>0` — `unitCost/(1+vat/100)`); оплачено по закупке = Σ `Payment.amount` COMPLETED с `purchaseId` + доля `Payment` по аукциону (`auctionSession`, `purchaseId IS NULL`), пропорционально итогу закупки; на лоты — пропорционально полной стоимости. Разрезы: `GROUP BY yr`, `GROUP BY auc` (первая строка `auctionSession`, иначе «Без аукциона»), `GROUP BY rm.name`.
- **[Q-итоги]** — Σ `purchaseTotalInclVat`: для позиций `costPlan.unitCostInclVat*quantity` (если заполнены `unitCostInclVat`, `materialExclVat`, `expenseExclVat`) иначе `subtotal*exchangeRate*(1+vatRate/100)`, плюс Σ расходов `PurchaseExpense` (их 0).
- **[Q-целостность]** — проверки `lotId`, `purchaseId`, материалов, количества, остатков (`quantityRemaining` против `quantityReceived − Σ ProductionMaterialUsage.quantity` и против `StockMovement`), отрицательных остатков, `|subtotal − quantity*unitPrice|>1`, `|totalCost − quantityReceived*unitCost|>1`.
- **[Q-НДС]** — `leaf WHERE (yr=2025 AND vat<>20) OR (yr=2026 AND vat<>22)`; `RawMaterialLot.vatRate` по году закупки.
- **[Q-поля]** — подсчёты `auctionSession IS NULL / ILIKE 'Нет информации%' / 'Не в реестре%' / 'Подкладочные%'`, пустые `transferDocument`, `invoiceNumber`, даты `orderDate`, `receivedDate` (`::date = '2026-10-01'`).
- **[Q-платежи]** — Payment по аукционам и закупкам; формула дашборда: Σ положительных остатков аукционов + закупки без аукциона − Σ `Payment` с `purchaseId IS NULL AND auctionSession IS NULL AND status='COMPLETED'` (поставщик один).
- **[Q-долг]** — как Q-платежи; значения 394 935 609,89 / 2 288 000,01 / 66 947 142,00 получены прямыми Σ.
- **[Q-партии]** — по ТЗ: `ProductionOrder` + Σ `ProductionMaterialUsage.totalCost` (мех и `RawMaterial.unit='M'` — подкладка), 4% = `Σ totalCost*0.04` для `commission4=true` (эквивалент `price4` при любой ставке НДС), работа = `clientWorkPricePerUnit * (producedQuantity>0 ? producedQuantity : plannedQuantity)`, оплаты через `ProductionPaymentOrder`, каждая оплата один раз по партии.
- **[Q-сходимость]** — по лотам: `Σ quantityReceived`, `Σ ProductionMaterialUsage.quantity`, `Σ StockMovement ADJUSTMENT_OUT`, `Σ quantityRemaining`; стоимость — `totalCost`, `usage.totalCost`, `quantityRemaining*unitCost`.
- **[Q-документы]** — подсчёты `DriveDocument` по колонкам привязки, `PurchaseDocument`; манифест `docs-inventory/drive-manifest.json` сопоставлен с `DriveDocument.driveFileId` (391 файл привязан, 223 нет).
- Сверка с документами: JSON отчётов `docs-inventory/extract/prod*.json` (`workOrders[].tzNumber/quantity/workPricePerUnit`) против `ProductionOrder.workOrderNumber`, суммы партий — таблицы md-отчётов; UPD-суммы закупок — p2025a/p2025b/p2026a/p2026b.md.

Ограничения: суммы по документам для платёжек (раздел 3.4) взяты из pending-decisions-purchases.md без повторного чтения Drive; построчная сверка цен ТЗ 70–112 невозможна (в JSON отчётов цены не выгружены); сумма «шкуры подрядчика» по партиям 5–9 и их связь с закупками «Нет информации» (п. 4 итога) — гипотеза по описанию платежа и отчётов prod2025a/b, требует подтверждения владельцем.
