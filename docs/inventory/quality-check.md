## Шаг 3. Скрипт

`scripts/link-drive-docs-quality.ts` — DRY-RUN по умолчанию, `--apply`, `--rollback <журнал>`, журнал
`docs-inventory/corrections-journal-drive-links-3.json`, план `docs-inventory/drive-links-plan-quality.txt`.
Привязывает только 4 однозначные пары (файл расчёта доплаты партии × закупка), по одной строке на закупку.
Защиты: файл-источник уже есть в базе; закупка найдена и не отменена; сумма закупки с НДС равна сумме из расчёта (±1 ₽);
ключ идемпотентности файл+закупка; дубль пары в таблице решений — ошибка.

Проверено на scratch-БД: dry-run (4 к созданию) → `--apply` (создано 4, DriveDocument 1031 → 1035) →
повторный `--apply` («Нечего применять», 0 новых) → дублей по всем внешним ключам в таблице нет →
страница-логика: у 0001, 0010, 0011, 0013 пропал пробел «Расчёт», покрытие закупок 212/249 → 216/249 →
`--rollback` вернул 1031 строк. Журнал тестового запуска удалён.

Запуск на боевой:
1. `scripts/backup.sh`
2. `node --env-file=.env node_modules/.bin/tsx scripts/link-drive-docs-quality.ts` — смотрите вывод (ожидается 4 к созданию, 0 пропущено)
3. `node --env-file=.env node_modules/.bin/tsx scripts/link-drive-docs-quality.ts --apply`
4. Откат при необходимости: `... --rollback docs-inventory/corrections-journal-drive-links-3.json`

## Шаг 4. Предлагаемые правки правил (код не менял)

В src/lib/doc-coverage.ts, функция `purchaseRules` (и признак `realAuction` в вызове из `computeDocCoverage`):

1. «Счёт аукциона» нужен только у закупки на реальном аукционе. Сейчас `realAuction = auction && !isServiceAuction(auction)`,
   а в `SERVICE_PREFIXES` (src/lib/auction-names.ts) нет меток «Подкладка Спец.», «Доп. материалы Спец.», «КФХ». Добавить их
   (или отдельный признак `directSupplier`). Уйдёт 7 пробелов. Побочный эффект: эти закупки в списке будут в группе «Без аукциона» —
   для подкладки и доп. материалов это верно; для фермы КФХ Дуденко проще завести отдельную проверку в `purchaseRules`, не трогая группировку.
2. Закупки-«сырьё подрядчика» (`transferDocument` начинается с «Доп закупк» либо заметка `[fix-structure:note]` «не отдельная закупка»,
   либо лот «лиса» у З-2026-0001): УПД и Спецификация — `na`, Расчёт — `optional` (расчёт — это расчёт доплаты партии, см. привязки).
   Уйдёт 10 пробелов. Надёжнее всего пометить такие закупки явным признаком (поле/тег), а не по тексту.
3. Для принятых закупок «Нет информации» и прямых закупок у ВеллМех (подкладка, лиса): Расчёт и Спецификация — `optional`,
   если нет аукциона (`realAuction=false`); обязательны только при аукционе. Уйдёт до 8 пробелов (0008, 0009, 0012, 0032, 0059, 0060 по Расчёту
   и 0008, 0009 по Спецификации). Применять осознанно: это снижает требования, а не исправляет данные.
4. ТЗ «Ремонт пальто» (П-2026-0183) создано из реестра, приложения нет по определению: можно сделать `TZ_APPENDIX` необязательным для ТЗ
   с пометкой `[open-items:tz116]`, либо оставить красным как напоминание.

Если принять правки 1–2, красных пробелов по закупкам останется 37 − 4 − 17 = 16 (из них 8 — настоящие инвойсы Saga, 2 — спецификации,
6 — расчёты с вопросом).
